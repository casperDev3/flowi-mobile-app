# TIMER-01 — таймер завдання та переходи статусів

Дата: 2026-09-21. Гілка: `feat/notes-ipad-workspace`.

## Симптом і причина

На телефоні та планшеті деталь завдання могла залишатись у стані «таймер не запущений» після натискання старту. `getTimerForTask` був стабільним callback, що читав mutable ref. Для мемоізованого споживача його залежності не змінювались. Мемоізована перевірка відтворила проблему: запис у реєстрі вже є, а деталь усе ще отримує `undefined`.

Друга проблема стосувалась завдань проєкту: старт і стоп записували особисті `status-in-progress` / `status-review`. Власні колонки проєкту мають інші id, тому дошка не знаходила цільову колонку. Обидві проблеми містились у спільному провайдері, який використовують телефон і планшет.

## Зміна поведінки

- Читання таймера тепер залежить від React-стану `activeTimers`. Мемоізована деталь отримує актуальні запуск і зупинку. Аналогічний getter нарад виправлено тим самим способом.
- Старт переводить завдання у власну колонку проєкту «У процесі»; стоп — у власну «На перевірці», додаючи завершену сесію. Для особистих завдань залишаються системні особисті колонки.
- Відповідність визначається через `sourceStatusId`, точну стандартну назву, а для процесу також через `type=in_progress`. Для перевірки не використовується загальний `type=todo`, бо він також означає «До роботи».
- Ручне завершення завдання зберігає «Готово» при автоматичній зупинці таймера.
- Якщо проєкт має власні колонки, але потрібної відповідності немає, застосунок показує повідомлення uk/en. Старт без колонки процесу не виконується. Стоп без колонки перевірки зберігає час і поточну колонку. Власнику потрібно налаштувати відповідний статус; довільні назви без `sourceStatusId` автоматично не вгадуються.
- Автоматика не створює проєктних колонок: сервер дозволяє змінювати workflow лише власнику (`core/sync_contract.py`, `PROJECT_OWNER_WRITE_COLLECTIONS`). Це запобігає локальним колонкам, які учасник не може синхронізувати.

## Перевірка

Нові три регресійні сценарії перевіряють мемоізовану деталь і проєктний цикл із наявною/відсутньою колонкою перевірки. На попередньому провайдері всі три падають, після виправлення проходять. Наявні тести відліку перевіряють самостійне зростання часу; перевірки завершення й реєстру — недублювання сесій та збереження статусу «Готово».

Підсумкові перевірки:

- Jest: 133 набори, 1803 тести — успішно.
- TypeScript: без помилок.
- ESLint змінених файлів: без помилок і попереджень.
- Expo production export для iOS та Android з React Compiler: успішно. Це перевірка JS/Hermes-пакетів, не встановлення нативної збірки на пристрій.
- `git diff --check`: успішно.

## Межі

Це виправлення спільного коду mobile. Web, серверні контракти й схеми не змінювались. Нативну перевірку нової збірки на фізичних iPhone/iPad/Android у цьому етапі не виконано. Попередні скриншоти й нативні перевірки нотаток не є доказами цього виправлення. Для встановленого застосунку потрібна нова збірка з цим комітом; публікація та розгортання не виконувались.
